# User Research

## Objective  
To understand user behaviors, pain points, and experiences when performing digital payment transactions.

## Industry Context  

Modern fintech platforms are designed to:

- Enable seamless digital payments  
- Support individuals and businesses at scale  
- Provide reliable, fast, and secure transactions  
- Abstract complex financial infrastructure into simple user experiences  

However, across platforms, a consistent challenge remains:
**ensuring transaction reliability and user trust.**

## Target Users  

This analysis focuses on three primary user segments:

- Retail users (peer-to-peer transfers, bill payments)  
- Businesses and merchants (payment acceptance)  
- Agents and intermediaries (assisted transactions)  

## User Personas  

### 1. The Retail Customer (Everyday Users)

**Profile:**
- Digitally active individual using mobile apps for transfers and bill payments    
- Performs frequent low to mid-value transactions
- Comfortable with mobile banking but sensitive to errors  

**Goals:**
- Send money quickly  
- Receive instant confirmation  
- Avoid errors, delays, reversals and failed transactions 

**Frustrations:**
- Failed transactions after debit  
- Delayed alerts  
- Unclear error messages  

### 2. Businesses and merchants (Small and Medium Business Owners)

**Profile:**
- Runs a small or medium-sized business
- Accepts digital payments from customers  
- Depends on consistent transaction flow for operations
- May use APIs or payment links

**Goals:**
- Receive payments reliably
- Reconcile transactions easily
- Avoid transaction and reversal disputes  
- Maintain customer trust  

**Frustrations:**
- Payment delays affecting operations and cash flow thereby affecting revenue 
- Disputes due to unclear transaction status 
- Difficulty tracking payments

### 3. Agents and intermediaries (The Mobile Money Agent)  

**Profile:**
- Facilitates transactions for multiple customers daily 
- Handles high daily transaction volumes
- Operates in environments with variable network quality  

**Goals:**
- Fast and reliable transaction processing  
- Minimal failure rates  
- Clear transaction outcomes  

**Frustrations:**
- Frequent transaction failures  
- Network instability  
- Loss of customer trust
- Customer dissatisfaction

## User Journey (Sending Money)

### Step 1: Initiate Transaction  
User enters recipient details and amount  

### Step 2: Confirm Transaction  
User reviews and confirms payment  

### Step 3: Processing  
System communicates with external financial services  

### Step 4: Outcome  
- Success → Transaction completed  
- Failure → Error occurs  

### Step 5: Post-Transaction  
User checks status or retries  

## Key Pain Points  

### 1. Transaction Failures  
- Increased failure rates during high system load  
- Dependency on third-party financial institutions  

### 2. Poor Error Communication  
- Vague or technical error messages  
- No clear next steps for users  

### 3. Lack of Transparency  
- Users do not know transaction status in real time  
- Delayed confirmations  

### 4. Retry Friction  
- No guided retry process  
- Fear of duplicate debits  

## Key Insights  
- Reliability is more critical than speed in financial transactions  
- Trust is easily lost after failed transactions  
- Users expect immediate and clear feedback  
- Businesses prioritize consistency over features  
- Transparency reduces support burden and increases user confidence  

## Opportunity Areas  

Based on user needs and industry patterns:

### 1. Reliability Optimization  
- Improve transaction routing and fallback systems  
- Reduce dependency failure impact  

### 2. Smart Retry Systems  
- Introduce guided retry mechanisms  
- Prevent duplicate transactions  

### 3. Real-Time Visibility  
- Provide live transaction status updates  
- Improve confirmation systems  

### 4. Improved Error Communication  
- Simplify error messages  
- Provide clear next steps  

## Research Note  

This analysis is informed by publicly observable product patterns and user experiences across leading fintech platforms, including Paystack, Flutterwave, and Stripe.

It is intended to model real-world fintech user behavior and system challenges.
